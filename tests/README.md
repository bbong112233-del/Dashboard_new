# 회귀 검증

대시보드를 고친 뒤 **기존 기능이 깨지지 않았는지** 확인하는 도구입니다.
코드를 읽어 판단하지 않고, 실제 Chromium 을 띄워 사람이 하듯 클릭한 다음
화면에 그려진 값을 직접 읽어 확인합니다.

이번 작업에서 잡은 버그 상당수가 "상태값은 멀쩡한데 화면이 안 바뀌는" 종류였습니다.
(예: 상세 팝업이 내용은 다 채워놓고 열리지 않아 `display:none` 으로 남아 있던 건)
코드만 읽어서는 찾을 수 없어 이 방식을 씁니다.

## 실행

```bash
npm install                 # 처음 한 번
pip install openpyxl        # 가상 데이터(xlsx) 를 만드는 데 필요
npx playwright install chromium   # 브라우저가 없다면
./tests/run-all.sh          # 전체 실행
./tests/run-all.sh tests/verify-proposal-view.js   # 한 종만
```

`TEST_PORT` 로 포트를, `PW_CHROMIUM` 으로 Chromium 실행 파일 경로를 지정할 수 있습니다.

## 검증 스위트

| 파일 | 다루는 것 |
|---|---|
| `verify-bulk-memo` | 일괄 메모 (여러 거래처에 같은 메모) |
| `verify-proposal-tracking` | 제안 진행/성사/실패, 메모·공지 3개월 보관 |
| `verify-firm-history` | 거래처 메모 이력 (흩어진 키를 시간순으로 합쳐 보기) |
| `verify-proposal-pick` | 기존 메모에 품목을 골라 제안 등록 |
| `verify-proposal-scope` | 제안이 거래처 단위로만 잡히는지 (코스 제외, 담당 채움) |
| `verify-proposal-entrypoints` | 성장가능·검색·인사이트·상품별 팝업의 제안 등록 |
| `verify-proposal-view` | 제안 현황 뷰 (정렬·경과일·상태 필터) |
| `verify-proposal-multi` | 한 거래처에 품목별 여러 제안 |
| `verify-proposal-date` | 제안 등록일은 오늘, 기존 메모 작성일은 보존 |

## 데이터

**실제 매출 자료는 저장소에 올리지 않습니다.**
`make-fixture.py` 가 매번 가상 데이터를 새로 만듭니다 — 회원사는 `거래처-001`,
코스는 `코스가(A)`, 상품은 `조명상품1` 같은 지어낸 이름이고 금액은 난수입니다.
검증 스크립트도 이름에 의존하지 않습니다. 화면에서 첫 번째 행을 집어오는 식이라
데이터가 바뀌어도 그대로 돕니다.

`make-testcopy.py` 는 실제 HTML 에서 Firebase SDK 를 떼어내고 `databaseURL` 을
무력화한 사본을 만듭니다. **테스트가 팀 데이터에 닿지 않게 하는 안전장치**이므로
이 단계를 건너뛰지 마세요.

생성물은 `tests/.fixture/` 에 들어가고 `.gitignore` 대상입니다.

## 고칠 때 주의

- **날짜를 고정값으로 쓰지 마세요.** 메모는 1개월이 지나면 '지난 메모'로 접히고
  3개월이 지나면 보관함으로 들어갑니다. `Date.now() - 20*86400000` 처럼
  오늘 기준 상대값을 쓰세요. (고정 날짜를 썼다가 5일 뒤에 깨진 전례가 있습니다)
- **앞 단계가 뒤 단계를 오염시키지 않게** 하세요. 메모를 저장하면 그 메모의 날짜가
  바뀌므로, 날짜를 검증할 대상은 별도 거래처로 분리해 두세요.
- 기능을 바꿔 단언이 깨지면, 먼저 **그게 의도한 변경인지** 판단하세요.
  의도한 것이면 단언을 새 사양으로 갱신하고, 아니면 코드를 고칩니다.
